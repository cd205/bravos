## executor.py logic being moved/absorbed (behaviour to preserve EXACTLY)

`_fetch_price(ticker, ibapp)` — allocate req_id under `_tick_lock`, install
`{"event", "price": None}` slot, `reqMarketDataType(3)`, `reqMktData(req_id, contract, "", False, False, [])`,
`slot["event"].wait(PRICE_WAIT_TIMEOUT)`, return `slot["price"]` or None, **always**
`cancelMktData(req_id)` in finally + pop slot under lock.

`_resolve_db_status(slot, order_id)` — IBKR_ERROR -> "REJECTED" (log ERROR w/ code+message);
`status is None` -> "UNKNOWN" (log ERROR "unverified"); else `_STATUS_MAP.get(raw, "UNKNOWN")`.
`_STATUS_MAP = {"PreSubmitted":"SUBMITTED","Submitted":"SUBMITTED","Inactive":"REJECTED"}`.

`gate._read_nlv(ibapp)`: `getattr(ibapp,"_account_summary",None) or {}`, `.get("NetLiquidation")`,

`gate.check` daily_pnl: `getattr(ibapp,"_daily_pnl",None) if ibapp is not None else None`.

## Bracket ordering constraint (why the order-slot API is decomposed — Task 1 builds it)

The bracket path today does: register parent slot → placeOrder(parent) → placeOrder(STP) →
placeOrder(TP[0..N-1]) → wait once on the parent slot. It must NOT wait between placing the
parent and placing the children (the last TP with transmit=True is what actually fires the
whole bracket at IBKR). A single atomic `place_order_and_wait` that does place+wait therefore
cannot serve the bracket. Task 1 splits the order-slot mechanism into two IBApp methods —
`_register_order_slot(order_id)` and `_await_registered_order(order_id, timeout) -> OrderResult`
— and defines `place_order_and_wait` as their composition (register → placeOrder → await).
The plain path calls `place_order_and_wait`; the bracket path calls register(parent) →
placeOrder(parent/STP/TPs) → await(parent). Both keep `_order_status_events` entirely inside
connection.py, so the executor grep-gate stays clean.
