<objective>
Fix the twice-confirmed "orderStatus-timeout-means-SUBMITTED" bug (IMPROVEMENTS.md item 3, IMPLEMENTATION_PLAN.md Session 1a). IBKR rejections arrive via the error() callback with reqId == orderId; orderStatus never fires; the executor's 3-second wait times out and records SUBMITTED. This masked two real rejections (EXEL error 321 Jul 2; HROW error 10268 Jul 8).

Two changes:
1. Route order-scoped error() callbacks into the _order_status_events slot (except informational warning codes — 399 confirmed) so a rejection wakes the waiting executor with a definitive answer.
2. Map the resolved slot honestly: IBKR_ERROR -> REJECTED (log ERROR), true timeout -> UNKNOWN (log ERROR), and only assign SUBMITTED when a real PreSubmitted/Submitted callback (or 399-then-Submitted) was observed.

Purpose: convert a silent failure-reported-as-success into a loud, correct DB record. Highest-value open trade-integrity item.
Output: corrected connection.py + executor.py, with tests covering rejection / 399-accepted / pure-timeout for both the bare and bracket submit paths.
</objective>
