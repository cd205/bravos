<objective>
Fix the IBKR internal auto-reconnect path so it refreshes IBApp's cached broker
state (NetLiquidation, positions, PnL subscription) after reconnecting — matching
what run_ingestion.py's _connect_ibkr() already does for the initial-connect and
SIGUSR2-resume paths.

Purpose: On 2026-07-06 a real BUY alert (HROW, signal_id=2540) was silently dropped.
IB Gateway threw error 504 at the moment the alert arrived; _reconnect_loop()
reconnected successfully but never re-ran startup reconciliation, so
ibapp._account_summary stayed empty. executor._calculate_quantity() read NLV as "0",
computed quantity=0, and execute_signal() skipped the order. Any transient blip
(504/1100/heartbeat timeout) coinciding with an alert can drop a live trade. This
must not happen again.

Output: IBApp._reconnect_loop() re-runs reconciliation + re-subscribes reqPnL on its
success path, using its own short-lived DB connection (the reconnect daemon thread
has no db_conn). Heartbeat thread is left alone (it survives disconnect and would be
duplicated if restarted). A regression test proves the account summary is repopulated.
</objective>
