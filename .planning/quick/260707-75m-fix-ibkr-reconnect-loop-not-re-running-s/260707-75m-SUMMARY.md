# Quick Task 260707-75m: Fix IBKR reconnect loop not re-running startup reconciliation Summary

Internal IBKR auto-reconnect (`_reconnect_loop`) now re-runs startup reconciliation and re-subscribes `reqPnL` on its success path, fixing the bug where a transient disconnect (e.g. error 504) coinciding with a trade alert left `_account_summary` empty, causing `_calculate_quantity` to read NetLiquidation as `"0"` and silently drop the order.

## What Happened

On 2026-07-06 a real BUY alert (HROW, signal_id=2540) was silently dropped: IB Gateway threw error 504 at the moment the alert arrived, `_reconnect_loop()` reconnected the socket successfully, but never re-ran the post-connect state refresh (`run_startup_reconciliation` + `reqPnL` re-subscription) that `run_ingestion.py._connect_ibkr()` performs on the initial-connect and SIGUSR2-resume paths. `ibapp._account_summary` stayed empty (`{}`), `executor._calculate_quantity()` read `NetLiquidation` as `"0"`, computed `quantity=0`, and `execute_signal()` skipped the order without any operator-visible failure.

This task closes that gap by adding `IBApp._refresh_after_connect()`, called from `_reconnect_loop`'s success branch immediately after the "IBApp reconnected" log line and before `_reconnecting` is cleared.

## Tasks Completed

### Task 1: Add `IBApp._refresh_after_connect()` and call it in `_reconnect_loop` success path
**Commit:** `c858fb9` — `fix(quick-260707-75m): re-run reconciliation on internal IBKR reconnect`

- Added module-level constant `REQ_ID_PNL = 9002` (mirrors `scripts/run_ingestion.py`'s `REQ_ID_PNL`, kept in sync manually; does not collide with `REQ_ID_ACCOUNT_SUMMARY = 9001`).
- Added `from bravos.config import settings` import for the DB field access pattern.
- Added `IBApp._open_short_lived_db_conn()` — opens a psycopg2 connection via `settings.DB_HOST/DB_PORT/DB_NAME/DB_USER` + `BRAVOS_DB_PASSWORD` env var, mirroring the existing inline pattern in `run_ingestion._get_db_connection()`. Caller is responsible for closing.
- Added `IBApp._refresh_after_connect()`:
  - Opens a short-lived db_conn, calls `self.run_startup_reconciliation(db_conn, timeout=30)`, closes the conn in a `finally` block. Wrapped in try/except — a DB failure is logged (`logger.exception`) but does not abort the reconnect.
  - Opens a fresh fill-callback connection and assigns `self._db_conn` (mirrors `_connect_ibkr`'s behavior of replacing `_db_conn` on every (re)connect). On failure, sets `self._db_conn = None` and logs.
  - If `self._account_name` is non-empty, calls `self.reqPnL(REQ_ID_PNL, self._account_name, "")` and logs. If empty, logs a warning and skips (mirrors `_connect_ibkr`).
  - Does NOT call `start_heartbeat_monitor()` — documented inline with a comment explaining the heartbeat thread survives disconnects and calling it again would spawn a duplicate `ibkr-heartbeat` thread.
- In `_reconnect_loop`, added `self._refresh_after_connect()` call in the `if success:` block, positioned after the "IBApp reconnected" log line and before `_reconnecting` is cleared under `_recon_lock` — exact order specified by the plan.
- Verify command passed: `_refresh_after_connect` exists, `REQ_ID_PNL == 9002`, `_reconnect_loop` source calls `_refresh_after_connect`, and `_refresh_after_connect` source does not call `start_heartbeat_monitor`.
