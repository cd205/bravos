<objective>
Make the Gmail alert-dispatch path honest and bounded (IMPROVEMENTS.md item 17).

Today `process_alert` is wrapped in `@catch_cycle_exceptions`, so it swallows every
exception and returns None whether it succeeded or failed. The socket handler
therefore replies "OK" even when nothing was stored. When a stored signal row is
missing (e.g. the July 7 HROW incident: Chrome was dead, nothing stored), the
poller's `_set_gmail_message_id` UPDATEs 0 rows, the email is never marked seen,
and it re-dispatches every poll cycle for hours. That accidental retry loop saved
the HROW trade — so we keep retry, but make it bounded (stop after 10) and honest
(OK means stored/duplicate, ERR means failed).

Purpose: no dispatch can report success where there was failure; no failing alert
can retry forever; the useful retry-on-transient-failure behavior survives.
Output: explicit `process_alert` contract, honest socket replies, bounded poller
retry with operator alert, 0-rows mark-seen fallback, and tests for all three.
</objective>
